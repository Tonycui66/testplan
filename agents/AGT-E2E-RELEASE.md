# AGT-E2E-RELEASE 功能说明

> 所属团队：QA Multi-Agent 测试团队  
> 统一入口：`../qa-agent-tasks.md`  
> 输入来源：`../plan.md`

## 1. 职责定位

`AGT-E2E-RELEASE` 负责跨模块端到端用户旅程和发布验收测试设计。它关注用户从登录到交付的完整链路，不负责单模块单元测试和 API 契约细节。

## 2. 核心功能

| 功能 | 说明 |
| --- | --- |
| 冒烟场景 | 登录、Dashboard、项目、流水线、测试、部署、度量、通知 |
| 项目闭环 | 迭代、需求、任务、Bug、看板流转 |
| CI/CD 闭环 | 创建、触发、查看、取消流水线，查看实时日志 |
| 测试闭环 | 创建用例集、用例、测试计划，执行测试 |
| 部署闭环 | 创建环境、触发部署、查看部署历史 |
| 发布验收 | Phase 0-4 发版前检查 |
| 环境准备 | Docker Compose 启动和测试数据初始化 |
| 外部依赖替换 | 使用 Mock 服务替代真实 GitLab、Docker daemon、SSH |

## 3. 输入

- `../plan.md` 第 8、9、10、13 章。
- `AGT-API-INTEGRATION` 的接口前置条件。
- `AGT-FRONTEND-COMPONENT` 的页面和交互测试结果。
- `AGT-INFRA-GATE` 的启动和健康检查结论。

## 4. 输出

- E2E 冒烟场景清单。
- 关键用户旅程脚本步骤。
- 回归场景清单。
- 发布前验收清单。
- E2E 环境准备和测试数据初始化方案。

## 5. 工作流程

1. 从 Phase 0-4 提取用户可见业务闭环。
2. 为每个闭环设计 Playwright 冒烟和回归场景。
3. 定义测试数据准备和清理规则。
4. 明确真实外部依赖的 Mock 或替身。
5. 将 Phase 0-4 质量门禁纳入发布验收清单。
6. 输出 E2E 和发版验收文档。

## 6. 负责与禁止范围

### 负责

- 跨模块全链路。
- 冒烟和回归场景。
- 发版验收。
- 测试环境和数据准备。

### 禁止

- 不设计 service 层单元测试。
- 不逐条设计所有 API 契约。
- 不深入 CI、DB、迁移内部实现。

## 7. 验收标准

- [ ] 覆盖 Phase 0-4 关键业务闭环。
- [ ] 覆盖健康检查、登录、项目、看板、流水线、测试、部署、度量和通知。
- [ ] 不使用真实外部凭据。
- [ ] 每个场景可追溯到 `plan.md` 阶段或风险项。

## 8. 与其他 Agent 的交接

| 交接对象 | 交接内容 |
| --- | --- |
| `AGT-API-INTEGRATION` | E2E 场景对应的 API 前置条件和数据状态 |
| `AGT-FRONTEND-COMPONENT` | 页面可操作性和关键交互路径 |
| `AGT-BACKEND-UNIT` | E2E 依赖的业务规则 |
| `AGT-INFRA-GATE` | 环境启动、healthcheck 和发布门禁 |
